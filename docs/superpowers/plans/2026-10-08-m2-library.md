# M2 Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Daily-driver browsing: Home, Explore, artist / playlist / mix pages, the collection with favorites, a queue panel, a disk cache, and the M2 performance checks (frame pacing, no idle repaint, display-size textures).

**Architecture:** `tidal` gains v2 requests, a raw-body disk cache with stale-while-revalidate primitives, and normalized browse models: every page becomes `Vec<Shelf>` of `Item`s whatever its TIDAL schema. `app` gets one generic page store keyed by `Route`, one backend loader that serves the cached page and then revalidates, and shared widgets (virtual rows, card, shelf, grid, header) that every view uses.

**Tech Stack:** Rust 2024, egui/eframe 0.36 on fastframe v0.4.1 (+ fastframe-scroll), tokio, reqwest 0.13 (rustls), serde, sha2, image 0.25.

**Spec:** `docs/superpowers/specs/2026-10-07-tidash-design.md` (§6, §7, §9, §10, §13 M2). Research behind this plan: the endpoint and pattern notes summarized in Task 1's spike doc.

## Global Constraints

- License `GPL-3.0-or-later`; edition 2024; `rust-version = "1.98"`; workspace lints unchanged; CI runs clippy with `-D warnings`.
- fastframe crates from `git = "https://github.com/crmne/fastframe", tag = "v0.4.1"` (Task 15 may pin `fastframe-fonts` alone to a rev).
- TLS rustls only. Tokens only in the OS credential store or memory; never logged, never in a file, never in a cache key or cache file.
- `player` depends on no tokio, HTTP client or `tidal` types; `tidal` on no UI or audio crate.
- Tests never touch the network, except `#[ignore]` live tests and the Task 1 recorder run by hand.
- Soft limit ~800 lines per file; one file per view.
- Look up every library API with ctx7 before using it (`npx ctx7@latest library <name> "<topic>"`, then `npx ctx7@latest docs <id> "<topic>"`).
- All user-visible strings through fastframe-i18n `tr`/`tr_n`; English only; update `crates/app/po/tidash.pot`.
- `tidal` re-exports from its crate root every public type named in an Interfaces block.
- No spinner (it repaints every frame) except while a request is pending; every failure path replaces it.
- Request conventions (official desktop client 2026.09.30): v1 GETs add `countryCode`, `locale=en_US`, `deviceType=DESKTOP`; v2 GETs (`https://api.tidal.com/v2/`) add the same plus `platform=DESKTOP` and header `x-tidal-client-version: 2026.9.30`. Task 1 may change `DESKTOP` values; then they change everywhere.

## Review Focus

1. **Offline or flaky network while browsing:** cached pages stay visible with an "Offline" banner, no error per page; an uncached page shows a retry, never an endless spinner. Test in Task 7.
2. **Very large lists (10 000 favorite tracks, long playlists):** all pages load in a few seconds (parallel pages), rows are virtualized, memory stays bounded. Tests in Tasks 4 and 9.
3. **TIDAL adds a module or item type, or omits an optional field:** the page still renders; the unknown part is skipped. Test in Task 4.
4. **A favorite write fails (network, 4xx):** the heart reverts and one error shows; the id sets stay what the server holds. Test in Task 11.
5. **Queue edits while playing (move, remove, play next, shuffle toggle):** the playing track keeps playing and stays current; removing the current track plays the next one. Tests in Task 12.
