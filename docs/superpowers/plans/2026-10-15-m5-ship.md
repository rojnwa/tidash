# M5 Ship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.0.0: signed self-update, installers and archives for Windows, macOS and Linux built on a tag, `tidal://` links registered on every OS, the performance budget measured by a script, and the docs.

**Architecture:**
- fastframe moves to v0.6.0, which also retires the fonts pin.
- `fastframe-update` runs on a thread of its own (every call blocks), over a 25-line `Transport` on our reqwest 0.13 (its own adapter is reqwest 0.12). The backend forwards the user's actions to that thread; its state reaches the UI as `Event::Update`.
- `main` runs the updater's `intercept` first and answers `--version` before the single-instance claim.
- Packaging follows Spotifast v0.13.3, cut down to what v1 needs:
  - a `v*` tag builds four native Linux and Windows runners and one macOS runner;
  - a `publish` job behind the `release-signing` environment signs `checksums.txt` with Ed25519 (native-packages' `sign-release`) and publishes the release;
  - native-packages' shared workflow then builds deb, rpm and AppImage from the published tar.gz.
- macOS links arrive as Apple Events, handled by a small objc2 module.

**Tech Stack:** Rust 2024; egui/eframe 0.36 on fastframe v0.6.0 (adds `fastframe-update`); reqwest 0.13 blocking; `anyhow` 1 (the updater's error type). On macOS, `objc2` 0.6 and `objc2-foundation` 0.3. For Windows builds, `winresource` 0.1. CI tools: Inno Setup 6, native-packages 0.9.0 (gem and shared workflow), nFPM 2.47.0.

**Spec:** `docs/superpowers/specs/2026-10-07-tidash-design.md` (§3, §7, §8, §10, §11, §13 M5). Research notes (session scratchpad, not kept; every brief quotes what it needs): fastframe v0.6.0 at commit `0d65ca9`, Spotifast at tag `v0.13.3` and native-packages at `83bd46c245488c2b8f1b9d74569e16cf6a449e8f` (v0.9.0). ## Rulings

These are decisions the spec leaves open. The human can overturn any of them in plan review.

- **R1. Windows installer: Inno Setup only, no MSI.** fastframe-update installs a `-setup.exe` when a release has no `.msi`. Spotifast ships both only to move its old Inno installs to MSI, which needs WiX, a Python build script and two C custom actions. Tidash has no installed base.
- **R2. No pre-release toggle.** fastframe-update offers pre-releases only to a build that is itself one (`Prereleases::WhenRunningPrerelease`), so a toggle in a stable build could do nothing. Tidash sets that mode: a release candidate is offered the next candidate and the release; a release never sees a candidate. Spec §7 drops "pre-release channel".
- **R3. One update setting: Automatic updates, on by default.**
  - On: checks at start and every 24 h (in memory, as Spotifast does), and downloads a release this copy can install.
  - Installing always waits for a click on "Restart to update"; quitting never installs.
  - A ready update is announced once, through the notice strip.
  - "Check now" works with the setting off.
- **R4. Signing.**
  - macOS: native-packages notarizes when all six `APPLE_*` secrets are set, and a partial set fails the build.
  - Windows: code signing is not wired. There is no account, and a step nobody can run is a guess.
  - Builds are unsigned until accounts exist; spec §11 is amended.
- **R5. No start-at-login.** It is not in v1's scope (§3), so there is no autostart argument; R21's `ping` stays unused. Recorded in follow-ups.
- **R6. The drawn mark is the app icon.** `tray::icon` draws it at any size. An ignored test writes the packaging rasters from it: the macOS 1024 px PNG, the Windows `.ico`, and hicolor PNGs. Replace the art later if wanted.
- **R7. Identity.**
  - Bundle id `io.github.rojnwa.Tidash`; executable `tidash` in every package.
  - Windows ProgId `Tidash.tidal`, and a new Inno `AppId` GUID, never Spotifast's.
  - Package maintainer: `Roman Wagner <rojnwa@users.noreply.github.com>`, not a work address.
- **R8. Windows media overlay ("Unknown app").** The exe gets a version resource (`ProductName`/`FileDescription` "Tidash") and the icon via `winresource`, as Spotifast does. An explicit AUMID waits until acceptance shows that the version resource alone does not fix it.
- **R9. Linux packages.**
  - deb, rpm and AppImage are built from the published tar.gz, for release candidates too, so `rc.1` exercises them.
  - They get native-packages' unsigned `packaging-checksums.txt`. They are not updater payloads: the updater refuses package-manager copies, and an AppImage does not update itself.
- **R10. A log file.** A Windows release exe has no console, so stderr goes nowhere. Logs go to `<data dir>/tidash.log` (replaced each run) and panics to `<data dir>/panic.log`, through fastframe-log's `file`/`panic_log`.

- [ ] **Step 5: Implement `update.rs`.**
  ```rust
  //! Self-update from GitHub releases (spec §8): fastframe-update over our reqwest 0.13, on a
  //! thread of its own, as every updater call blocks.

  pub const CONFIG: UpdateConfig = UpdateConfig {
      macos: MacConfig {
          bundle_ids: &["io.github.rojnwa.Tidash"],
          executable_names: &[], // the slug, `tidash`
          legacy_bundle_names: &[],
      },
      publisher_key: Some(include_str!("../assets/update-public-key.hex")),
      // A release candidate is offered the next one and the release; a release never a candidate.
      prereleases: Prereleases::WhenRunningPrerelease,
      ..UpdateConfig::new("rojnwa/tidash", "Tidash", "tidash", env!("CARGO_PKG_VERSION"))
  };

  /// What the backend asks of the update thread.
  #[derive(Debug, PartialEq)]
  pub enum Command {
      /// The user asked: check now, then download what is new.
      Check,
      /// The Automatic updates setting changed.
      Automatic(bool),
      /// Hand the downloaded update to the helper, then quit.
      Install,
  }

  /// The update thread; it ends when the returned sender is dropped (the backend stops).
  pub fn start(emit: Arc<Emitter>, automatic: bool) -> Sender<Command> {
      let (tx, rx) = std::sync::mpsc::channel();
      let spawned = std::thread::Builder::new().name("updates".into()).spawn(move || {
          match Http::new() {
              Ok(http) => run(&Updater::new(CONFIG, http), &rx, automatic, CHECK_INTERVAL, &|ev| emit.send(ev)),
              Err(e) => log::warn!("no update checks: {e}"),
          }
      });
      if let Err(e) = spawned {
          log::error!("update thread failed: {e}");
      }
      tx
  }
  ```
  - **`run(updater, rx, automatic, every, emit: &dyn Fn(Event))`** keeps `next: Instant` (now at start) and `prepared: Option<Prepared>`. It loops on `rx.recv_timeout(next_wait(automatic, prepared.is_some(), next, Instant::now()))`; `recv_timeout` blocks for good on `Duration::MAX`, since std falls back to `recv` when the deadline overflows.
    - Timeout: set `next = now + every`, then `prepared = check(updater, false, emit)`.
    - `Check`: while nothing is prepared, `prepared = check(updater, true, emit)`; with a ready update, nothing.
    - `Automatic(on)`: set `automatic = on`. Turning it on checks at once if `next` has passed.
    - `Install`: if `prepared.take()` gives one, `install`.
    - Disconnected: return. The updater, and the blocking client in it, drop on this thread.
  - **`check(updater, asked, emit) -> Option<Prepared>`:**
    - Emit `Checking` only when `asked`.
    - `updater.check()`:
      - `Ok(None)`: emit `UpToDate` when asked.
      - `Err(e)`: `log::info!("update check failed: {e:#}")`; when asked, emit `Failed(UpdateStep::Check)`.
      - `Ok(Some(release))`: go on.
    - `updater.installation()` `Err(reason)` → `Unsupported { version, reason }`, and nothing is downloaded.
    - Else `updater.download(&release, progress)`. `progress` emits `Downloading { version, percent }` only when the whole percent changes (`received * 100 / total`, 0 when `total` is 0, at most 100).
      - `Ok(prepared)`: emit `Ready { version }`, then the notice `Event::Error(tr("Tidash {version} is ready. Restart to update it in Settings › Updates.").replace("{version}", &version))`. Return it.
      - `Err(e)`: `log::warn!`, emit `Failed(UpdateStep::Download)`.
  - **`install(updater, prepared, emit)`:**
    - `updater.handoff(prepared, Vec::new())`; the relaunch takes no arguments.
    - `Ok` → emit `Event::Quit`. The app's quit path runs the normal shutdown, and the helper waits up to 60 s for the exit.
    - `Err` → `log::warn!`, emit `Failed(UpdateStep::Install)`.
  - **`Http`**, as the research note gives it:
    ```rust
    /// fastframe-update's transport over our reqwest 0.13 (its `ReqwestTransport` is 0.12): every
    /// status comes back as is, and redirects are the updater's, which follows them only to
    /// GitHub's release hosts.
    struct Http(reqwest::blocking::Client);

    impl Http {
        fn new() -> reqwest::Result<Self> {
            reqwest::blocking::Client::builder()
                .redirect(reqwest::redirect::Policy::none())
                .connect_timeout(Duration::from_secs(15))
                .timeout(Duration::from_secs(15 * 60))
                .build()
                .map(Self)
        }
    }

    impl Transport for Http {
        fn get(&self, request: &Request<'_>) -> anyhow::Result<Response> {
            let response = self.0.get(request.url)
                .header(ACCEPT, request.accept)
                .header(USER_AGENT, request.user_agent)
                .send()?;
            let location = response.headers().get(LOCATION).and_then(|v| v.to_str().ok()).map(str::to_owned);
            Ok(Response { status: response.status().as_u16(), location, body: Box::new(response) })
        }
    }
    ```

- [ ] **Step 1: `.github/workflows/release.yml`.** It is Spotifast's release workflow cut down (R1, R4, R9), with the dry run added. Each step:

  ```yaml
  name: Release

  on:
    push:
      tags: ["v*"]
    workflow_dispatch: # a dry run: every package is built and uploaded as a workflow artifact

  permissions:
    contents: read

  env:
    CARGO_TERM_COLOR: always
  ```
  - **`build`** (matrix, `fail-fast: false`):

    | os | target | pe-machine |
    |---|---|---|
    | ubuntu-24.04 | x86_64-unknown-linux-gnu | |
    | ubuntu-24.04-arm | aarch64-unknown-linux-gnu | |
    | windows-latest | x86_64-pc-windows-msvc | `8664 machine (x64)` |
    | windows-11-arm | aarch64-pc-windows-msvc | `AA64 machine (ARM64)` |

    Steps:
    1. `actions/checkout@v7`; `dtolnay/rust-toolchain@stable` with `targets: ${{ matrix.target }}`. No cache: published binaries never build from restored outputs.
    2. On Linux, the apt packages from `ci.yml`.
    3. On Windows, `ilammy/msvc-dev-cmd@v1` with `arch: x64|arm64`.
    4. **Version** (bash):
       ```bash
       version=$(cargo metadata --no-deps --format-version 1 | jq -r '.packages[] | select(.name == "tidash") | .version')
       if [[ "$GITHUB_REF_TYPE" == tag ]]; then
         [[ "$GITHUB_REF_NAME" == "v$version" ]] || { echo "tag $GITHUB_REF_NAME is not v$version"; exit 1; }
         [[ -f "packaging/release-notes/$GITHUB_REF_NAME.md" ]] || { echo "no packaging/release-notes/$GITHUB_REF_NAME.md"; exit 1; }
       fi
       echo "TAG=v$version" >> "$GITHUB_ENV"
       ```
    5. `cargo build --release --locked -p tidash --target ${{ matrix.target }}`.
    6. **Check** (bash): `target/<target>/release/tidash --version` equals `tidash ${TAG#v}`.
    7. On Windows, Spotifast's dumpbin check: no `MSVCP*`/`VCRUNTIME*` import, and the PE machine matches.
    8. **Package** (bash):
       - `name=tidash-$TAG-<target>`, `dist/$name/` holding the binary, `README.md`, `LICENSE`, `packaging/tidash-portable.txt`, `packaging/licenses/Inter-LICENSE.txt`, and `crates/app/assets/icons/LICENSE.txt` as `icons-LICENSE.txt`;
       - on Linux also `cp --parents packaging/applications/tidash.desktop` and the `packaging/icons/hicolor` tree;
       - then `7z a "$name.zip" "$name"` (Windows) or `tar czf "$name.tar.gz" "$name"` (Linux) in `dist`.
    9. On Windows, the **installer** (pwsh), as Spotifast's: ISCC with `/DVersion=${TAG#v} /DArch=<x86_64|aarch64> /DBinary=… /DOutputDir=$PWD\dist packaging\windows\tidash.iss`.
    10. **Budget** (bash): fail if any `dist/*.zip`, `*.tar.gz` or `*-setup.exe` is 20,000,000 bytes or more (`wc -c`). Spec §10: installer < 20 MB.
    11. `actions/upload-artifact@v7`, named after the target, with those three globs and `if-no-files-found: error`.
  - **`macos`** (`macos-latest`). Job `env` maps the six secrets `APPLE_CERTIFICATE_P12`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_TEAM_ID` and `APPLE_APP_PASSWORD`; none set means ad-hoc signing (R4). Steps:
    1. Toolchain with `aarch64-apple-darwin,x86_64-apple-darwin`, then the same Version step.
    2. Both `cargo build --release --locked -p tidash --target …`, then `lipo -create … -output universal/tidash`.
    3. `bash packaging/macos/bundle.sh universal/tidash dist/macos-input/Tidash.app "${TAG#v}"`.
    4. Copy `README.md`, `LICENSE`, `Inter-LICENSE.txt` and `icons-LICENSE.txt` into `dist/macos-input/`.
    5. `dist/macos-input/Tidash.app/Contents/MacOS/tidash --version` equals `tidash ${TAG#v}`.
    6. `ruby/setup-ruby@v1` (`ruby-version: '4.0'`), `gem install native-packages --version 0.9.0 --no-document`.
    7. `native-packages build --version "${TAG#v}" --target macos-universal --defer-recipes --output "$RUNNER_TEMP/macos-packages"`, then copy `$RUNNER_TEMP/macos-packages/packages/macos-universal/dmg/*.dmg` to `dist/`.
    8. The same Budget step on `dist/*.dmg`, then upload `macos-universal`.
  - **`publish`**:
    - `needs: [build, macos]`, `if: github.ref_type == 'tag'`, `runs-on: ubuntu-latest`.
    - `environment: release-signing`, so it waits for the human's approval and is the only job with the key. `permissions: contents: write`.
    - Steps:
      1. `actions/checkout@v7` with `persist-credentials: false`.
      2. `actions/download-artifact@v7` with `path: dist`, `merge-multiple: true`.
      3. The source archive: `curl --fail --location --retry 3 "https://github.com/$GITHUB_REPOSITORY/archive/refs/tags/$GITHUB_REF_NAME.tar.gz" -o "dist/tidash-$GITHUB_REF_NAME-source.tar.gz"`.
      4. `ruby/setup-ruby@v1` (`'4.0'`).
      5. Sign:
         ```yaml
         - uses: crmne/native-packages/.github/actions/sign-release@83bd46c245488c2b8f1b9d74569e16cf6a449e8f # v0.9.0
           env:
             TIDASH_UPDATE_SIGNING_KEY: ${{ secrets.TIDASH_UPDATE_SIGNING_KEY }}
           with:
             directory: dist
             public-key: crates/app/assets/update-public-key.hex
             key-env: TIDASH_UPDATE_SIGNING_KEY
         ```
      6. `softprops/action-gh-release@v2` with `files: dist/*`, `name: Tidash ${{ github.ref_name }}`, `body_path: packaging/release-notes/${{ github.ref_name }}.md`, `generate_release_notes: false` and `prerelease: ${{ contains(github.ref_name, '-') }}`. Not a draft: the packaging job downloads the published tar.gz.
  - **`packaging`**: `needs: publish`, `if: ${{ !cancelled() && needs.publish.result == 'success' }}` (release candidates too, R9), `uses: ./.github/workflows/packaging.yml` with `version: ${{ github.ref_name }}`, and `permissions: contents: write`.

### Task 8: The performance budget, scripted

**Files:**
- Create: `packaging/budget.sh` (macOS and Linux), `packaging/budget.ps1` (Windows)
- Modify: `crates/app/Cargo.toml` (`log`), `docs/superpowers/specs/2026-10-07-tidash-design.md` §10, `docs/follow-ups.md`

**Interfaces:**
- Produces: `packaging/budget.sh <tidash binary>` and `packaging/budget.ps1 <tidash.exe>`. Each prints, one line each:
  - `first frame: N ms`;
  - `RAM after Home: N MB` (macOS: `footprint`'s physical footprint; Linux: `Pss` from `/proc/<pid>/smaps_rollup`; Windows: working set and private bytes);
  - `idle passes in 10 s: N`;
  - `CPU idle: N.N % of one core` (CPU time over 10 s of wall time: macOS `ps -o time=`, Linux `/proc/<pid>/stat` utime+stime, Windows `TotalProcessorTime`);
  - `binary: N MB`.

  Each exits non-zero if a §10 target is missed: first frame ≥ 500 ms, RAM ≥ 150 MB, or any idle pass.

Remove that part of the follow-up.

  - Header comment: what each target means, and that CPU paused-hidden, CPU playing-minimized and scroll pacing (PresentMon, Windows) stay manual, as listed in `docs/releasing.md`.

## Execution notes

- **Workspace:**
  - The worktree is `.claude/worktrees/m5-ship` on a new branch from `origin/main`, never tracking it: `git worktree add --no-track -b feature/m5-ship .claude/worktrees/m5-ship origin/main`.

  - Subagents run on `opus-xhigh`; the final whole-branch review on `fable-xhigh`. Then finishing-a-development-branch.
- **Order:**
  1. Task 1.
  2. Task 2, whose Step 1 is the controller's.
  3. Task 3.
  4. Task 4.
  5. Task 5.
  6. Task 6.
  7. Task 7.

  Tasks 5 and 6 do not depend on 2–4 and may run beside them if the controller keeps the `main.rs` edits apart. Task 6's link handling touches the launch code Task 3 changes, so run it after.
- **Human gates. Approval in one does not carry to the next:**
  - storing the signing key and creating the environment (Task 7 Step 5);
  - pushing the branch and running the workflows (Task 7 Step 8);
  - launching Tidash on the human's desktop (Task 6 Step 5, Task 8 Step 3);
  - merging to `main`;
  - each tag (Task 9 Steps 6, 7 and 9).

  The private key is never printed, committed or copied anywhere but the GitHub secret and the human's backup.
- **Untestable before a release:** download, verification and handoff need a signed, published release, so Task 9 Step 7 is their test. Task 2's tests stop at the check and the installation verdict.
