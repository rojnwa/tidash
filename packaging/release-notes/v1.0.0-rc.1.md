The first release candidate of Tidash 1.0: a native TIDAL client for Windows, macOS and Linux, with no browser engine.

This is a pre-release for testing. Its main job is to check that installing and self-update work on every platform: it updates itself to the next release candidate and then to 1.0.0, while a 1.0 install is never offered a candidate.

## What it does

- Browse Home, Explore, Search, artists, albums, playlists and mixes; your collection, favourites, playlists and folders, with editing.
- Lossless and Hi-Res FLAC playback, gapless, with ReplayGain and bit-perfect exclusive output (WASAPI, Core Audio hog mode, ALSA `hw:`).
- Queue, synced lyrics, credits, track and artist radio.
- Media keys and the system's now playing, a tray icon with close to tray, single instance and `tidal://` links.
- ListenBrainz scrobbling. Last.fm and Discord Rich Presence need build-time keys that these builds do not have yet, so Settings does not show them.
- Self-update with signed releases: Settings › Updates.

## Install

See the [README](https://github.com/rojnwa/tidash#install). Builds are not code-signed yet: on Windows choose More info › Run anyway; on macOS open the app once through System Settings › Privacy & Security › Open Anyway.

## Performance (macOS, M2 Pro)

First frame after 272 ms, 128 MB on Home, no redraws and 0.1% of one core while idle, a 17.2 MB binary.

## Known limitations

- No code signing yet (SmartScreen and Gatekeeper warn).
- The deb, rpm and AppImage do not update themselves; install the new package from this page.
- Last.fm and Discord are not in these builds (no keys yet).
- Start at login, Flatpak, AUR and Homebrew are not there yet.

Bug reports: attach `tidash.log` (where to find it is in the README).
